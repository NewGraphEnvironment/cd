## Outcome

`cd_plot_timeseries()` and `cd_plot_comparison()` now label series from the `long_name` / `unit` carried on the input, through the #92 helpers rather than a second copy of the `cd_variables()` lookup, so a series from another package (streamflow) plots with the label `cd_summary()` prints. `cd_compare()` gained a `long_name` pass-through (raw values, so no unit — `cd_trend()`'s rule). Two things learned. First, `unit` is the **anomaly's** unit, so raw-value plots were mislabelled (raw prcp mm read "Precipitation (%)"); the rule for when an anomaly unit also describes raw values (`absolute`, `pct_point_diff` only) now lives once, in `meta_resolve(raw = TRUE)`, and `cd_trend()`/`cd_summary()` still disagree with it on raw input (cd#97). Second, the shared-`long_name` facet fix was itself defective in its first form — a one-pass ` (variable)` suffix can collide with another real label — which review round 2 caught inside the fix; the mechanism was a display label used as an identity key, closed structurally by faceting on variable + label, and an enumeration of every grouping/join/facet key in consumer code found no other site. Review: plan review (11 findings) plus `/code-check` 4 rounds on Phase 1 and 3 rounds + enumeration on Phase 2; findings files are in this directory. Spun off cd#96 (vpd registry unit is Pa, data hPa), cd#97, cd#98 (`cd_summary()` rows indistinguishable for stations sharing a `long_name`).
